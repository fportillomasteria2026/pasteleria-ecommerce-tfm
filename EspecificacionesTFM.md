# Normativa y Requisitos Oficiales - Trabajo Fin de Máster (TFM)

## 1. Objetivo Principal
*   **Creación de Software Real:** Elaborar una aplicación original adaptada a tu nivel de conocimientos y experiencia.
*   **Demostración de Competencias:** El proyecto debe demostrar los conocimientos adquiridos a lo largo del máster, ser diferenciador y aportar valor personal.
*   **Libertad Tecnológica:** Se permite desarrollar cualquier tipo de software (web, app, utilidad, herramienta, juego, etc.). El enfoque es agnóstico en cuanto a tecnología.

## 2. Requisitos de los Entregables (Obligatorios)
Para que el TFM sea revisado y calificado, se deben cumplir y entregar los siguientes 5 puntos:

### 2.1. Documentación Completa (`README.md`)
Debe incluir obligatoriamente las siguientes secciones:
*   Descripción general del proyecto.
*   Stack tecnológico utilizado.
*   Información sobre su instalación y ejecución.
*   Estructura del proyecto.
*   Funcionalidades principales.
*   Usuario y contraseña de prueba (si el proyecto requiere login).

### 2.2. Código Fuente
*   **Repositorio Público:** El código debe estar alojado en un repositorio público en GitHub.
*   **Excepción (Repositorio Privado):** Solo se permite si está perfectamente justificado. En ese caso, es obligatorio conceder permisos de acceso al email `mouredev@gmail.com`.

### 2.3. Despliegue en Producción
*   **Proyecto en Funcionamiento:** Publicación del proyecto para su utilización real (recomendado siempre que sea posible).
*   Se debe incluir la URL o el acceso al proyecto real dentro de la documentación (`README.md`).

### 2.4. Presentación (Slides)
*   Soporte visual del proyecto creado con herramientas como Google Slides, PowerPoint o Canva.
*   Se debe incluir la URL de acceso público a la presentación o adjuntar el documento en el repositorio (y enlazarlo en la documentación).

### 2.5. Vídeo Demostrativo
*   **Explicación y Demo:** Vídeo subido a plataformas como YouTube o Google Drive.
*   **Captura de Pantalla:** Es estrictamente obligatorio capturar la pantalla mientras realizas la explicación y muestras el funcionamiento.
*   **Cámara:** Mostrar el rostro durante la grabación es opcional.
*   La URL de acceso público al vídeo debe constar en la documentación.

## 3. Estructura del Directorio del Código
Dentro de la raíz del repositorio de GitHub debe encontrarse fácilmente:
*   El archivo de documentación (`README.md`).
*   La información de acceso al despliegue.
*   El enlace o archivo de las slides.
*   El enlace al vídeo explicativo.

## 4. Instrucciones para la Entrega Oficial
La entrega se realiza exclusivamente a través del formulario habilitado en la descripción de la lección del Proyecto Final.

**Campos obligatorios a cumplimentar en el formulario:**
*   Nombre completo del alumno.
*   Email utilizado en la inscripción del máster.
*   URL del repositorio de GitHub.
*   URL de despliegue o publicación (si aplica).
*   URL de las slides.
*   URL del vídeo.
*   Usuario y Contraseña de prueba (si aplica).
